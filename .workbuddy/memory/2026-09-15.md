## 圆桌发言加 TTS 语音播放（百度短文本在线合成）

新增能力：每条角色发言右侧一个 🔊 按钮，点击合成并播放。用户消息不显示按钮。

接口关键事实（已由用户 curl 验证，不要怀疑）：
- `POST https://tsn.baidu.com/text2audio`，`Authorization: Bearer <QIANFAN_API_KEY>` **可直接用**，不需要换 Access Token
- body 为 `application/x-www-form-urlencoded`：`tex/cuid/ctp=1/lan=zh/spd/pit/vol=5/per/aue=3`（aue=3 → mp3）
- 成功返回二进制 + `Content-Type: audio/mp3`；失败返回 `application/json`（含 err_no/err_msg）→ **成功判据只看 Content-Type 是否以 audio/ 开头**

四个角色音色（TTS_VOICES，定义在 llmClient.js）：advocate 4194 spd6 pit5（度嫣然活泼女声）、critic 4195 spd4 pit4（度怀安磁性男声）、researcher 4197 spd5 pit5（度沁遥知性女声）、moderator 4106 spd5 pit5（度博文专业男主播）。未知名回落 moderator 音色。

改动（4 文件）：
- `api/_lib/llmClient.js`：新增 `TTS_URL`、`export const TTS_VOICES`、`export async function callTTS({ text, role, timeout = 15000 })`；URLSearchParams 拼 body；AbortController 超时；返回 ArrayBuffer，失败抛 Error（含 err_no）。头部注释同步为「LLM + 语音合成」。
- `api/chat.js`：新增 `if (body.mode === 'tts') return handleTTS(req, res, body)` 分支 + import。**该文件是 Node runtime（无 edge 声明），所以 res.send(Buffer) 可用**。
- `api/_lib/ttsHandler.js`（新）：`handleTTS`，校验 text/role、300 字截断防御、TTS_TIMEOUT=15000、成功 `Content-Type: audio/mp3` + `Cache-Control: no-store` + `res.send(Buffer.from(ab))`、失败 500 JSON。
- `src/components/RoundtableWidget.vue`：`playingId` ref + 模块级 `currentAudio`/`playToken`；`playMessage(msg)`（点同一条=停，点另一条=先 stopPlay 再播；fetch → blob → createObjectURL → Audio.play，onended 清理）；`stopPlay()`（pause + revokeObjectURL + 重置）；`onUnmounted(stopPlay)`；消息长度 watch 在 len===0 时 stopPlay（覆盖"清空记录/重新开始"）；meta 行末尾加 `.rt-msg-play` 按钮（`margin-left:auto` 推到最右，放在 R 轮次 chip 之后而非 duty 之后，否则轮次 chip 会被挤到按钮右侧）。

关键实现细节：用 `playToken` 令牌让在途请求失效，避免"A 的 fetch 晚到/失败时把已切到 B 的播放状态干掉"；blob URL 必须手动 revoke（不会随 Audio 回收）。

验证：node --check 三文件通过；stub fetch 实测 4 角色 + 未知角色的 form body、失败分支抛出 `TTS 合成失败（err_no=502）: ...`；stub res 实测 handler 四条路径（200 二进制/400 缺参/300 字截断/500 JSON）；vite build 通过（EXIT=0）。

## 排错：mode:'tts' 在本地报「缺少必要参数: dataset_id, query」

根因不是代码问题，是**本地 dev 没有本地后端**：`vite.config.js` 的 `server.proxy['/api']` 指向生产域名 `https://bdxxg.asia`，所以 `localhost:5173/api/chat` 被转发到线上后端，而线上那份 chat.js 是已推送版本、还没有 tts 分支（本次 TTS 改动全部未提交）。实测线上 `mode:'roundtable'` → 「缺少 topic 或 role」（分支存在），`mode:'tts'` → dataset_id 报错（分支不存在）。
